PHASE 3: DuckDB Structured Storage ✅
  File: app/structured/duckdb_store.py (250 LOC)
  - Per-tenant OLAP storage: one DB, kb_{id}_upload_{id} tables
  - Parameterized queries only (no LLM SQL generation)
  - Size caps: 100MB or 1M rows per file
  - Methods: write_table, query, delete_table, list_tables, get_table_info
  
PHASE 4: Column Resolver ✅
  File: app/structured/column_resolver.py (100 LOC)
  - SINGLE SOURCE OF TRUTH for semantic→physical mapping
  - Function: resolve_semantic_column(role, schema) → column_name or None
  - Only returns high-confidence (≥0.85) mappings
  - Called by: planner, executor, validator
  
PHASE 5: Schema-Aware Query Planner ✅
  File: app/structured/query_planner.py (300 LOC)
  - Converts natural language → validated JSON QueryPlan
  - Detects: operation (SUM/COUNT/AVG), metric, date filters, compatible datasets
  - Whitelisted operations only (no free-form SQL)
  - Selects compatible uploads that have required metric
  
PHASE 6: Plan Compiler ✅
  File: app/structured/plan_compiler.py (250 LOC)
  - Converts QueryPlan → parameterized DuckDB SQL
  - Multi-file UNION with column aliasing to canonical schema
  - Safety: resolves semantic→physical, uses parameters, rejects non-whitelisted ops
  - Output: (sql_string, params_dict)
  
PHASE 7: Structured Query Executor ✅
  File: app/structured/structured_executor.py (150 LOC)
  - Executes compiled plans via DuckDB
  - Returns results with FULL PROVENANCE (which files, which columns)
  - Example output: {result: 71, sources: [{filename, physical_metric, ...}, ...]}
  
PHASE 8: Table-Aware Chunking ✅
  File: app/ingestion/chunking/table_aware.py (150 LOC)
  - Groups rows logically (not character-count splitting)
  - Preserves header in each chunk
  - Never splits rows mid-record
  - For semantic search on tables ("what trends?")
  - Falls back to recursive for PDF/DOCX (unchanged)

ARCHITECTURE SUMMARY
================================================================================

INGESTION PIPELINE (Phases 1-4, 8):
  CSV/XLSX Upload
    ↓
  [Schema Discovery] → Detect columns, types, semantic roles
    ├─ High confidence (≥0.85) → MAPPED
    └─ Low confidence → AMBIGUOUS_SCHEMA (flagged, not blocking)
    ↓
  [Persist Schema] → StructuredFileSchema in Postgres
    ↓
  [Parallel Storage]
    ├─ DuckDB: Raw rows (for aggregations)
    ├─ Vector DB: Table-aware chunks (for semantic search)
    └─ Postgres: Schema metadata (for planning)

QUERY-TIME PIPELINE (Phases 5-7):
  User Query
    ↓
  [Routing Decision]
    ├─ Structured Route: "How many products?" → SUM/COUNT/etc
    │   ├─ Query Planner: Generate QueryPlan
    │   ├─ Plan Compiler: QueryPlan → Parameterized SQL
    │   ├─ Executor: DuckDB execution
    │   └─ Result: {value, provenance, sources}
    │
    ├─ Semantic Route: "What's important?" → Vector search
    │   └─ Result: {retrieved_chunks, similarity_scores}
    │
    └─ Hybrid Route: Both structured + semantic
        └─ Result: {structured_result, semantic_context, combined_answer}
