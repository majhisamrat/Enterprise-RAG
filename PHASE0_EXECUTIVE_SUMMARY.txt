================================================================================
THE PROBLEM
================================================================================

When users select a Knowledge Base and query, retrieval returns ZERO documents
even when matching content exists. This is a critical bug that breaks KB-scoped
retrieval entirely.

Root Cause: Two compounding bugs in vector payload storage and KB filtering:

Bug 1: document_name stored as UUID ("doc_12345") instead of filename
Bug 2: KB post-filter checked wrong field ("title" instead of "document_name")
Result: Filters silently removed all KB-scoped results

================================================================================
THE FIX
================================================================================

THREE MINIMAL FILE CHANGES:

1. app/services/ingestion_service.py (1 line)
   - Add: document_name=doc_title parameter to vector storage call

2. app/retrieval/hybrid.py (~30 lines)
   - Add: allowed_upload_ids parameter for unambiguous filtering
   - Improve: Two-tier filtering (upload_id primary, filename fallback)
   - Improve: Check document_name before document_id in payload lookup

3. app/orchestrator/rag.py (~5 lines)
   - Add: Collect upload IDs from KB uploads
   - Add: Thread upload_ids to retriever

TOTAL: ~40 lines of code changed across 3 files
TYPE: Pure bug fix, no new features or API changes
RISK: LOW (backward compatible, surgical changes)
